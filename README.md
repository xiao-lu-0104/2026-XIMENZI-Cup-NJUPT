# 工业嵌入式数据采集终端（GD32F470）

> **2026 CIMC「西门子杯」工业嵌入式系统开发赛项 —— 初赛软件部分满分作品**
>
> 基于 GD32F470VET6 的数据采集终端：模拟量采集、参数持久化、RS485 协议解析、定时上报与阈值告警、低功耗唤醒、Bootloader / OTA 在线升级。

---

## 一、项目简介

一个面向工业现场的数据采集节点：以 GD32F470VET6 为主控，实现模拟量采集、串口协议交互、参数掉电保存、定时上报与异常告警、低功耗管理及远程固件升级，并配套自研系统电源板、PT100 采样板与模拟板。

**数据通道定义**

| 通道 | 物理来源 | 说明 |
| :--: | :-- | :-- |
| CH0 | 电位器 | 片内 ADC 采样，乘变比后上报 |
| CH1 | DAC 回读 | DAC 输出经跳线回读（PA4 → PC1），乘变比后上报 |
| CH2 | 外部 ADC | GD30AD3344 采样 PT100，换算为实际温度（℃） |

---

## 二、主要功能

- **数据采集**：ADC + DMA 循环采样（CH0/CH1），SPI 外挂 GD30AD3344 采集 PT100，5 点中值滤波 + PT100 分度换算。
- **模拟输出**：12 位 DAC 输出（0~4095），设定值掉电保存、上电恢复。
- **人机交互**：软件 I2C OLED 双行显示（第一行为设备编号，第二行为 `IDLE` / `AutoSample` / `Bootloader`）；LED 状态指示。
- **通信协议**：自定义帧格式，ASCII 字符串承载 HEX 报文，CRC-16/MODBUS 校验，命令 / 应答 / 心跳 / 错误四类帧。
- **参数持久化**：设备 ID、波特率、变比、阈值、告警使能、DAC 设定值写入内部 Flash，双备份 + CRC32 校验。
- **定时上报**：1 s / 3 s / 5 s 可选间隔，上报 RTC 时间 + CH0 + CH1。
- **告警**：三通道阈值判断，最多缓存 10 条告警记录，支持主动上报、查询与清除。
- **低功耗**：收到睡眠命令后进入 DeepSleep，RTC Alarm 10 s 唤醒并恢复全部外设。
- **Bootloader / OTA**：固件包魔术字校验、错误固件拒绝、分区搬运升级，升级标志保存在 RTC 备份寄存器（不擦写参数区）。

## 五、软件架构

```text
RS485 ──USART1 中断──▶ ring_buff ──▶ protocol_frame_parser ──▶ ASCII→HEX + CRC16
                                                        │
                                                        ▼
                                          Protocol_ParseBinary（命令分发）
                                                        │
                                    ┌───────────────────┴───────────────────┐
                                    ▼                                       ▼
                          业务处理（采样/参数/告警）                  应答组帧 → ASCII → RS485

TIM2 (1 Hz) ──▶ 事件队列 ──▶ LED 闪烁 / 自动上报 / 告警检测
TIM6        ──▶ AD3344 采样 ──▶ 中值滤波 ──▶ PT100 温度
```

- **中断只做最小工作**：串口中断仅入环形缓冲，命令解析与业务处理在主循环完成；定时器中断只投递事件，避免长耗时操作阻塞采样。
- **事件队列解耦**：`EVENT_LED_Toggle` / `EVENT_AUTO_REPORT_SEND` / `EVENT_ALARM_CHECK` / `EVENT_ENTER_SLEEP` / `EVENT_SOFT_Reset` 等事件由主循环统一消费。
- **App 独立运行**：`System_Init()` 中重设 `SCB->VTOR = 0x08011000` 并清空 NVIC 挂起标志，保证从 Bootloader 跳转后中断向量正确。

## 六、通信协议

### 6.1 物理层与编码

- RS485 半双工，8 位数据位、无校验、1 位停止位。
- 报文按 HEX 组帧后**转换为 ASCII 字符串**发送（如帧头 `0xA5B6` 实际发送字符 `'A''5''B''6'`），接收端同样按 ASCII 解析。

### 6.2 帧格式

| 字段 | 长度 | 说明 |
| :-- | :--: | :-- |
| 帧头 | 2 B | 固定 `0xA5B6` |
| 设备 ID | 2 B | `0x0001~0xFFFE` 有效，`0xFFFF` 为广播 |
| 帧类型 | 1 B | `0x01` 命令 / `0x02` 应答 / `0x05` 心跳 / `0xFF` 错误 |
| 命令字 | 2 B | 大端 |
| 内容长度 | 1 B | 内容字段字节数 |
| 协议版本 | 1 B | 固定 `0x02` |
| 内容 | N B | 命令数据 |
| CRC16 | 2 B | CRC-16/MODBUS，范围：帧头 ~ 内容末尾，大端 |
| 帧尾 | 2 B | 固定 `0xB6A5` |

**应答约定**：成功应答为 `0x02` + 原命令字 + 1 字节 `0xFF`；数据查询应答为 `0x02` + 原命令字 + 数据（浮点数为 4 字节大端 IEEE754）；异常应答为 `0xFF` + `0xEEEE`。

### 6.3 已实现命令字

| 命令字 | 功能 | 内容 / 应答 |
| :-- | :-- | :-- |
| `0x0101` | 设备重启 | 应答 OK 后软复位 |
| `0x0104` | 查询固件版本 | 应答 `02 00 01 00`（V2.0.1.0） |
| `0x0105` | 设置设备时间 | 内容 4 B 大端秒计数；应答 OK |
| `0x0106` | 查询设备时间 | 应答 4 B 大端秒计数 |
| `0x0111` | 查询设备 ID | 应答 2 B |
| `0x01A1` | 设置设备 ID | 内容 2 B（`0x0001~0xFFFE`）；保存后应答 OK |
| `0x0112` | 查询波特率 | 应答 1 B 编码 |
| `0x01A2` | 设置波特率 | 内容 1 B（`0x11`~`0x14`）；OK 后 200 ms 软复位 |
| `0x0201` | 查询 CH0 | 应答 4 B float（V） |
| `0x0202` | 查询 CH1 | 应答 4 B float（V） |
| `0x0221` | 查询 CH2（PT100） | 应答 4 B float（℃） |
| `0x0241` | 设置 CH0 变比 | 内容 4 B float；保存后应答 OK |
| `0x0242` | 设置 CH1 变比 | 内容 4 B float；保存后应答 OK |
| `0x0261` | 设置上报间隔 | 内容 1 B：`1`→1 s，`2`→3 s，`3`→5 s |
| `0x0301` | 设置 DAC 输出 | 内容 2 B（0~4095），同时保存设定值 |
| `0x0302` | 启动定时自动上报 | 应答 OK，随后按间隔上报 `0x0302` 帧 |
| `0x0303` | 停止自动上报 | 应答 OK |
| `0x03AA` | 进入睡眠模式 | 应答 OK 后进入 DeepSleep |
| `0x0400` | 读取 CH0、CH1 阈值 | 应答 8 B（两个 float） |
| `0x0401` | 读取 CH0 阈值 | 应答 4 B float |
| `0x0402` | 读取 CH1 阈值 | 应答 4 B float |
| `0x0411` | 写入 CH0 阈值 | 内容 4 B float；保存后应答 OK |
| `0x0412` | 写入 CH1 阈值 | 内容 4 B float；保存后应答 OK |
| `0x0501` | 升级请求 | 应答 OK → 写升级标志 → 软复位进入 Bootloader |
| `0x0601` | 告警主动上报开关 | 内容 1 B：`0x01` 开启，`0x02` 关闭 |
| `0x0602` | 查询告警记录 | 以纯文本逐条回复；无记录回复 `empty\r\n` |
| `0x0603` | 清除告警记录 | 应答 OK |

**Bootloader 支持的命令**：`0x0111` 查询设备 ID、`0x0502` 准备接收固件、`0x0503` 执行升级，以及心跳广播 / 心跳应答。

### 6.4 特殊帧与非帧回复

| 场景 | 方向 | 内容 |
| :-- | :-- | :-- |
| 心跳广播 | 上位机 → 设备 | 帧类型 `0x05`，命令字 `0xFFFF` |
| 心跳应答 / 上电通知 | 设备 → 上位机 | 帧类型 `0x05`，命令字 `0x8888` |
| 异常应答 | 设备 → 上位机 | 帧类型 `0xFF`，命令字 `0xEEEE`（固件包校验失败时为 `0x0502`） |
| 告警查询结果 | 设备 → 上位机 | 纯字符串，不经帧封装：``YYYY-MM-DD HH:MM:SS \| CHx \| 阈值 \| 实测值\r\n`` |
| 无告警记录 | 设备 → 上位机 | `empty\r\n` |
| 睡眠唤醒 | 设备 → 上位机 | `instrument wakeup\r\n` |
| Bootloader 等待提示 | 设备 → 上位机 | 每秒输出 `wait for start Application(Ns)......\r\n` |

### 6.5 自动上报帧

`0x0302` 启动后，按设定间隔发送内容为 12 字节的上报帧：`RTC(4 B) + CH0(4 B float) + CH1(4 B float)`。
上报期间设备仅响应停止命令 `0x0303`，其余命令一律忽略。

## 七、Flash 分区与参数持久化

### 7.1 内部 Flash 分区

| 区域 | 起始地址 | 结束地址 | 大小 | 用途 |
| :-- | :-- | :-- | :--: | :-- |
| Bootloader | `0x08000000` | `0x0800FFFF` | 64 KB | 引导 / OTA |
| 参数区 | `0x08010000` | `0x08010FFF` | 4 KB | 应用参数 + 升级标志 |
| App | `0x08011000` | `0x08030FFF` | 128 KB | 应用程序 |
| App 备份区 | `0x08031000` | `0x08050FFF` | 128 KB | 预留 |
| 固件暂存区 | `0x08051000` | `0x08070FFF` | 128 KB | OTA 接收缓冲 |

### 7.2 参数管理

- 参数结构体带 `magic = 0xA5A5C33C`、`structSize` 与 **CRC32** 校验，A/B 双备份分别存放于 `0x08010200` / `0x08010600`；加载时依次校验，双份均失效则载入默认值并回写。
- 保存时先读取整页、只替换参数字段再整页擦写，避免破坏同页其他数据。
- **升级标志不写入参数区**，而是写入 RTC 备份寄存器 `RTC_BKP1 = 0xA55A5AA5`，防止 OTA 过程中反复擦写 4 KB 参数页。

**默认参数**

| 参数 | 默认值 | 参数 | 默认值 |
| :-- | :-- | :-- | :-- |
| 设备 ID | `0x0001` | 波特率 | `0x13`（19200） |
| CH0 / CH1 变比 | `1.0` | CH0 / CH1 阈值 | `3.0 V` |
| CH2 阈值 | `100.0 ℃` | 告警主动上报 | `0x02`（关闭） |
| DAC 设定值 | `0` | 固件版本 | `2.0.1.0` |

## 八、采样与换算

| 通道 | 换算方式 |
| :-- | :-- |
| CH0 | `V = ADC_raw × 3.3 / 4095 × 变比` |
| CH1 | `V = ADC_raw × 3.33 / 4095 × 变比` |
| CH2 | AD3344 采样 → 5 点中值滤波 → `R = V × 95.2 − 13.36` → `T = (R − 100) / 0.385055` |

- PT100 温度超出 −50~200 ℃ 判定为异常值，保持上一次有效温度。
- 每 30 次温度读取重新配置一次 AD3344 寄存器，避免外部干扰导致配置丢失。

---

## 九、告警机制

- 每 2 s 检测一次 CH0 / CH1 / CH2 是否超过对应阈值。
- 告警记录写入 10 条容量的环形缓冲区，格式为 `时间 | 通道 | 阈值 | 实测值`。
- `0x0601` 开启主动上报后，触发告警会立即以纯文本推送；否则仅本地记录。
- `0x0602` 按"最新在前"顺序回读，`0x0603` 清空记录。

## 十、低功耗流程

1. 收到 `0x03AA` 先回复 OK（延时 50 ms 确保发送完成）。
2. 关闭 USART1、TIM2、DMA、ADC、DAC 与 SysTick。
3. 配置 RTC Alarm 10 s 唤醒（EXTI_17）。
4. 调用 `pmu_to_deepsleepmode(..., WFI_CMD)` 进入 DeepSleep。
5. 唤醒后重配时钟与外设、恢复 DAC 输出与 OLED 显示，并发送 `instrument wakeup\r\n`。

---

## 十一、Bootloader 与 OTA 升级

**固件包格式**：`4 字节魔术字 0x5AA5C33C` + 固件镜像。

1. 上位机发送 `0x0501`（升级请求）→ App 应答 OK，写入 `RTC_BKP1` 升级标志并软复位。
2. Bootloader 启动时检测标志：有标志则 OLED 显示 `Bootloader`，清标志并开启 10 s 倒计时；无标志则延时 5 s 直接跳转 App（无任何串口输出）。
3. 上位机发送 `0x0502` → 擦除固件暂存区首页并进入接收状态，随后的数据以裸字节流写入。
4. 数据采用 8 KB 缓冲 + "500 ms 无新数据"判据落盘，落盘前按 4 KB 页逐步擦除（不整片擦除，缩短等待时间）。
5. 接收结束后校验暂存区首部魔术字：失败返回 `0xFF/0x0502` 错误帧；成功返回 `0x0502` 的 OK 应答并停止倒计时。
6. 上位机发送 `0x0503` → Bootloader 应答 OK，按页擦除 App 区、跳过 4 字节魔术字逐字节搬运镜像，最后 `NVIC_SystemReset()` 复位运行新固件。
7. Bootloader 跳转前会校验 App 区栈顶与复位向量（栈顶需落在 `0x20000000` 区域、复位向量需位于 Flash），校验不通过则停留不跳转，避免运行空片。

## 十二、编译与烧录

**环境**

- Keil MDK 5 + ARM Compiler 5（V5.06 update 5）
- 器件支持包：`GigaDevice.GD32F4xx_DFP.3.0.3`
- 调试器：J-Link / GD-Link

**步骤**

1. 用 Keil 打开 [Bootloader 工程](最终程序/Bootloader/project/CIMC_GD32_Template.uvprojx)，编译并下载（IROM1 已配置为 `0x08000000`，大小 64 KB）。

## 十三、项目说明

- 代码按 **Driver / Protocol / Function** 分层，业务逻辑与协议解析、底层驱动解耦。
- 协议解析使用静态环形缓冲 + 帧头帧尾检索，长度或 CRC 校验失败时丢弃当前帧并返回错误应答，不会阻塞主循环。
- 所有应答帧统一由 `Protocol_SendFrame()` 组帧，自动完成 CRC 计算与 ASCII 转换。
- 本仓库代码与硬件工程仅供学习交流。
